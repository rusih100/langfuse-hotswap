# langfuse-hotswap

*Горячая замена языковой модели в цепочке LangChain через промпт Langfuse.*

Управление промптами в [Langfuse](https://langfuse.com) выносит шаблон из кода: его правят в
интерфейсе, присваивают версии метку `production`, и сервис забирает её сам. Модель при этом
остаётся в коде. `gpt-5.5`, `temperature=0.2` и `max_tokens=800` прописаны рядом с цепочкой, и
любое их изменение требует коммита и деплоя. В результате промпт, подобранный под одну модель,
попадает в эксплуатацию с той моделью, которая была в последнем деплое.

`langfuse-hotswap` переносит модель в конфигурацию промпта:

```json
{"model": "gpt-5.5", "model_provider": "openai", "temperature": 0.2, "max_tokens": 800}
```

и предоставляет [LangChain](https://github.com/langchain-ai/langchain) `Runnable`, который при
каждом вызове получает промпт, собирает по нему цепочку `template | model` и пересобирает её,
когда промпт меняется. Код определяет, что разрешено менять через Langfuse; Langfuse задаёт
значения.

## Возможности

- **Одна версия промпта — одна модель.** Шаблон, провайдер, имя модели и параметры
  версионируются, помечаются и откатываются вместе.
- **Любой провайдер, поддерживаемый `init_chat_model`.** OpenAI, Anthropic, Google, Mistral,
  Ollama и остальные интеграции LangChain. Чтобы сменить провайдера, достаточно изменить
  конфигурацию.
- **Полноценный `Runnable`.** Поддерживаются `invoke`, `ainvoke`, `stream`, `astream`, `batch`,
  `abatch`, `batch_as_completed`, `astream_events`, `with_fallbacks`, `with_retry` и композиция
  с другими runnable.
- **Безопасность по умолчанию.** Из конфигурации берутся только известные параметры генерации.
  Адреса, ключи, заголовки, прокси, HTTP-клиенты, тайм-ауты и повторные попытки из неё не
  читаются никогда. Провайдер всегда указывается явно и не определяется по имени модели.
  Настройки в коде имеют приоритет над конфигурацией. См. раздел [Безопасность](security.md).
- **Устойчивость к сбоям.** Если новая версия промпта не собирается или Langfuse недоступен,
  последняя исправная цепочка продолжает обслуживать запросы, а ошибка записывается в журнал.
- **Правила подстановки Langfuse.** Переменные подставляются по тем же правилам, что и в
  Langfuse, — это закреплено контрактным тестом против SDK. Модель получает ровно то, что вы
  видите в playground. Плейсхолдеры поддерживаются.
- **Трассировка привязана к промпту.** Цепочка передаёт промпт в метаданных, поэтому трассы,
  собранные обработчиком обратных вызовов Langfuse, связаны с версией промпта.

## Сравнение с использованием SDK напрямую

SDK Langfuse уже предоставляет `get_prompt()` и `prompt.get_langchain_prompt()`. Прочитать
`prompt.config["model"]` и передать его в `init_chat_model` — дело нескольких строк. Ниже — то,
что в этих строках не учтено:

| | `get_prompt` + `init_chat_model` вручную | `langfuse-hotswap` |
|---|---|---|
| Модель следует за версией промпта | Реализуете сами | Да |
| Пересборка только при изменении промпта | Кешируете модель и сравниваете промпты сами | Сначала проверка идентичности объекта, затем сравнение по имени, версии, содержимому и конфигурации |
| Параллельные вызовы во время пересборки | Нужна блокировка | Сборка выполняется один раз, остальные вызовы обслуживает предыдущая цепочка |
| Новая версия не собирается | Каждый вызов завершается ошибкой | Предыдущая цепочка продолжает работать; ошибка записывается в журнал и сборка повторяется не чаще раза в минуту |
| Langfuse недоступен, кеш пуст | `get_prompt` выбрасывает исключение | `PromptFetchError`; при наличии собранной цепочки она продолжает работать |
| Редактор промпта указывает `base_url` или `api_key` | Попадает в конструктор модели | Не попадает никогда: белый список и список запрещённых ключей |
| Редактор промпта меняет провайдера | Любой установленный | Только провайдеры, настроенные в коде, и только по явному имени |
| `ainvoke` при холодном кеше SDK | Блокирует цикл событий на время HTTP-запроса | Запрос выполняется в пуле потоков; прогретый кеш читается в цикле событий |
| Подстановка переменных | `get_langchain_prompt()` заменяет `{{x}}` на `{x}` и экранирует скобки | Правила Langfuse, плейсхолдеры, отсутствующая переменная — ошибка |
| Структурированный вывод, инструменты, повторные попытки | Пересобираете вместе с моделью | `with_structured_output`, `bind_tools` и хуки `with_model` применяются при каждой пересборке |
| Связь трассы с версией промпта | Передаёте промпт в метаданных сами | Добавляется к каждому запуску |

## Когда библиотека не нужна

- **Один промпт, одна модель, менять её из интерфейса не планируется.** Достаточно
  `get_prompt()` и `init_chat_model()`.
- **Смена модели обязана проходить код-ревью.** Смысл библиотеки именно в том, что перенос метки
  меняет поведение в эксплуатации. В таком случае держите модель в коде, а Langfuse используйте
  только для шаблона.
- **Модель должна выбираться для каждого запроса** — по арендатору, по тарифу пользователя.
  Цепочка следует за промптом, а не за запросом. Создайте по цепочке на каждый промпт и
  распределяйте запросы между ними.
- **LangChain не используется.** Библиотека реализует `Runnable` LangChain и создаёт модели через
  `init_chat_model`.
- **Промпты редактируют люди, которым нельзя доверять.** Защита не подпускает их к адресам и
  ключам, но выбор модели, лимит токенов и, как следствие, стоимость остаются в их руках. Сначала
  ограничьте доступ к метке `production` в Langfuse.

## Требования

Python 3.11+, `langchain>=1,<2`, `langchain-core>=1,<2`, `langfuse>=5,<6`. Пакет содержит маркер
`py.typed`.

Неофициальный проект, не связанный с Langfuse и LangChain.
