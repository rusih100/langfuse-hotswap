# Обработка ошибок

Все исключения библиотеки наследуются от `HotswapError`.

## `PromptFetchError`

Промпт не удалось получить, а кеш SDK оказался пуст: например, холодный старт во время сбоя или
промпт был удалён. Если цепочка уже собрана, ошибка записывается в журнал не чаще раза в минуту, а
цепочка продолжает обслуживать запросы. Если собранной цепочки нет, исключение выбрасывается.

Восстановление остаётся на стороне приложения — например, запасная локальная цепочка:

```python
from langfuse_hotswap import PromptFetchError

chain = factory.create("support-reply").with_fallbacks([local_chain], exceptions_to_handle=(PromptFetchError,))
```

или запасной промпт, собираемый с моделью из аргументов фабрики (см. раздел
[Конфигурация](configuration.md#выбор-версии-промпта)).

## `ChainBuildError`

Промпт получен, но собрать цепочку не удалось: в конфигурации отсутствует `model` или не указан
провайдер, пакет провайдера не установлен, конструктор модели отклонил параметр, хук выбросил
исключение.

Если цепочка уже собрана, ошибка записывается в журнал, цепочка продолжает работать, а сборка
повторяется не чаще раза в минуту. Если собранной цепочки нет, исключение выбрасывается, и в
течение следующей минуты вызовы получают ту же ошибку без повторной сборки — так неисправный промпт
при холодном старте не создаёт модель на каждый вызов.

## Пакетная обработка

При `return_exceptions=True` методы `batch`, `abatch`, `batch_as_completed` и
`abatch_as_completed` возвращают ошибку для каждого элемента вместо выброса исключения. Для пустого
списка входных данных возвращается пустой результат, промпт при этом не запрашивается.

## Схемы

`get_input_schema` возвращает переменные промпта, когда Langfuse доступен, и разрешающую схему в
противном случае. `get_output_schema` в случае ошибки возвращает схему по умолчанию.
